# Methodology

The primary estimand is the ratio of expected candidate and reference runtimes in a warmed, isolated physical A100 setting, with the reference runtime in the numerator. The empirical reference pools arithmetic runtime means across independently invoked sessions before taking the log ratio. Gold capture has no controlled interference. A fixed task-specific measurement seed preserves inputs and model states across sessions. Correctness uses separately randomized inputs, checks dtype and shape, rejects input mutations, and uses KernelBench's 1e-4 FP32 absolute and relative tolerances. The device and candidate identity, recipe hash, and fixed measurement seed must agree across comparisons.

A paired observation is the log ratio of per-block arithmetic means. Averaging these observations estimates a log-block target. Jensen bias relative to the primary arithmetic-runtime target is part of measured estimator error. The paired observations store both roles and order. By default blocks choose RCCR or CRRC with equal probability. Explicit RCCR, CRRC and RCRC sequences are accepted through YAML. B0 invokes upstream cold-cache timing. M0 and M1 collect separate reference and candidate timing phases. M1 uses stronger warm-up and a ratio of medians. Gold analysis requires at least two sessions with 200 or more recorded blocks each. Individual launches within one CUDA event are subsamples and are accounted for in the event-duration sum.

Physical exploratory analysis samples entire gold sessions with replacement and uses a circular moving-block bootstrap within each session. Two sessions give a weak estimate of session variability. Pair order is unresolved when marginal reference intervals overlap. Sign metrics exclude reference signs that could change over the marginal interval box. This screening does not establish simultaneous coverage for all signs or ranks. Confirmatory analysis needs jointly sampled task vectors, shared session resampling, and prespecified multiplicity correction.

The CPU diagnostic predeclares four cases and three group sizes. It shares seeded latent outcomes and AR(1) streams across policies, and charges the same declared block cap within a group and budget. Per-candidate cost varies across the generated task. Paired and unpaired traces differ by the simulated drift term, so the pairing ablation checks behavior under that assumption. The CPU study reports exploratory group-bootstrap percentile intervals and paired differences over independently generated groups. No multiplicity correction was applied. Numerical coverage is checked against generated latent values after stopping.

The first panel uses 30 pinned tasks and six diagnostic candidates per task. Seven tasks are assigned to held-out evaluation by task ID. This split does not hold out entire operator categories. Public Dr. Kernel training data provide prompts and metadata. Natural groups need contemporaneously recorded unfiltered rollouts or a release with explicit sibling provenance.
